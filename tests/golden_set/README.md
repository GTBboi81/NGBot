# ゴールデンセット（評価用サンプル）

> **注意:** ここに含まれるのは公開用の**架空のサンプルデータ**です。
> 実運用で使用していた実際の通話データ（PIIを含む）は公開版には含まれていません。
> 本格的に評価する場合は、`tests/build_golden_set.py` を使ってご自身の環境の
> 日次CSVからゴールデンセットを構築してください。

## ファイル構成
- `{id}_input.txt` … LLMへの入力（文字起こしテキスト）
- `{id}_proposed.json` … モデルが出力した既存結果（レビューたたき台）
- `{id}_expected.json` … **人手レビュー後の正解**（`run_eval.py` はこれが在る件のみ評価）
- `manifest.json` … 全件のメタ情報（電話番号、テナント、文字数バケット、レビュー状況）

同梱の `sample_00N_*` は上記フォーマットの例です。`sample_00N_expected.json` を
用意してあるので、ローカルLLMを用意すれば `python tests/run_eval.py --model <tag>` が
そのまま動作します。

## レビュー手順（自前データを構築する場合）

各 `_proposed.json` を `_input.txt` と照らし合わせて確認:

1. `NG理由` が「判定の優先順位」に従っているか
   1. 留守 → 2. 今忙NG → 3. アプローチNG → 4. 具体的理由 → 5. 申込意思無NG → 6. その他
2. `利用回線` が「**顧客の明確な肯定**」根拠を満たすか
   - アポインター質問のみで顧客が肯定していない場合は **N/A** が正解
3. `NG理由箇所` が **顧客の発言** から逐語抜粋されているか
   - アポインターの発言は不可。会話に存在しない文字列は不可
4. `氏名` / `郵便番号` / `都道府県` は明示された場合のみ。推測は禁止

修正が必要なら `_proposed.json` を直接編集してから **`_expected.json` にリネーム**してください。

## セキュリティ注意
- 実データは氏名・電話番号・住所などのPIIを含むため、**外部送信・git管理・クラウド同期は禁止**
- 自前で構築した `_input.txt` / `manifest.json` 等は `.gitignore` 済み（`sample_*` のみ追跡）
